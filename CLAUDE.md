# cuems-editor

Part of the **CUEMS** ecosystem — see the [`cuems-RELATIONS`](https://github.com/stagesoft/cuems-RELATIONS) repo for the system index, architecture diagram, and protocol/port map.

## Role

WebSocket middleware for multi-user project editing and media management — sits between the browser frontend (`cuems-frontend`) and the engine (`cuems-engine`). Python 3.11+, systemd service `cuems-editor.service` (controller-side). PyPI name `cuemseditor`.

- **Frontend → Editor**: WebSocket `:9092`, JSON `{"action": "...", "value": ...}`.
- **Editor → Engine**: Unix IPC socket `/tmp/editor.ipc` (serialized objects) over NNG.

Main classes: `CuemsWsServer` (asyncio WS server / session multiplexer / command router), `CuemsWsUser` (per-connection session handler), `CuemsProjectManager` (owns the DB managers), `CuemsDBProject` (project CRUD, XML script I/O, filesystem management).

## Build

```bash
cd <this repo> && debuild -b -uc -us -nc
```

That is the command on a **bookworm** host. On a Debian 13 (trixie) development machine do not run it: it would target trixie, and dh-virtualenv bakes the host `python3` into the venv. Build inside an unprivileged bookworm chroot instead: `tests/packaging/bookworm-build.sh` (mmdebstrap `--mode=unshare`; needs `mmdebstrap`, subuid/subgid ranges, network). It builds the `cuemsutils` wheel from `../cuems-utils` because PyPI stops at rc14, and checks that the venv's `pyvenv.cfg` says `home = /usr/bin` and the chroot `python3` is 3.11.

## Project store / library — `/opt/cuems_library/`

The authoritative path is `settings.xml <library_path>` (read by the editor as `library_path`). **There is NO `/opt/cuems/` directory** — that was a long-standing doc error; everything project-related is under `/opt/cuems_library/`.

Contents:
- `projects/` — one dir per project, **named by `unix_name`**. The project UUID and display `name` live *inside* `script.xml` and in the index DB, **not** in the dir name.
- `media/`, `trash/`.
- `project-manager.db` — SQLite index (tables `project`, `media`, `projectmedia`).

## Field notes / gotchas

- **Save-time FadeCue validation** (`CuemsDBProject.validate_fade_durations_in_contents`, called in `update()` and `new()` before `CuemsParser`): rejects any FadeCue whose duration is missing, unparseable, or `<= 0` with a single `ValueError` naming the offenders (forwarded verbatim to the frontend over WS). Parsing delegates to the real cuemsutils `CTimecode` — its ms semantics are literal (`'.3'` = 3 ms) and `'00:00:03'` raises `IndexError`, so a private parser would diverge. `duplicate()` is deliberately NOT validated (legacy projects must stay duplicable; the engine's reveal guard covers them).
- **Dangling targets are the library's, not the editor's** (001): the editor's `_clean_dangling_targets` walk and its cue-type list are deleted. `cuemsutils` `target_resolves` repairs a dangling `Cue.target` on load; `action_target_resolves` refuses a dangling `action_target` (ActionCue and FadeCue) on load and at `CuemsScript.save`. Do not reintroduce a walk keyed on cue names: after cuems-utils 013 hardware cues are `Cue` with `class`, and the old walk nulled valid targets on every save.
- **`cuems-editor-repair-durations` never writes a script** (001, FR-027a). It corrects `media.duration` in the DB (pass A) and lists projects whose scripts still hold a different duration as `NEEDS_SAVE`. Script files change only when an operator opens the project in the editor and saves it; until that save, the engine plays the file on disk, short durations included. A script still in the pre-013 device shape is `SKIPPED_INVALID`: run `cuems-reshape-devices` over the whole library, then save in the editor.
- **After hand-editing `network_map.xml` or `default_mappings.xml`, restart BOTH `cuems-editor` AND `cuems-controller-engine`** (plus `cuems-node-engine` if active). Both daemons cache topology at startup via `ConfigManager(load_all=True)`; there is no on-disk reload. Restarting only the editor leaves the engine on the stale topology. Verify: editor logs `"number_of_nodes": N`.
- **The node list is pushed, not polled by clients.** `watch_network_map` (a 3 s mtime poll, one per host) broadcasts `node_list` (before payload version 1: `initial_mappings`) whenever **cuems-nodeconf** rewrites `network_map.xml` — which it does on every avahi event or every 30 s, since it is resident. Without this the editor only re-read the map on connect and after its own successful `nodelist_modify`, so a node powered on *after* the operator opened Settings never appeared in `new_nodes` and adoption looked broken exactly when it was needed. `nodelist_get` is the on-demand pull of the same payload; `nodeconf_available` in that payload (an envelope field, sampled per frame, absent from `initial_mappings`) says whether adoption can work on this host at all (`/tmp/nodeconf.ipc` present — it is absent on most of the fleet, where every adopt/un-adopt click can only fail). Protocol reference: `tests/ws-command-responses.txt`.
- **`network_map.xml` is cuems-nodeconf's; the editor never writes it** (002). nodeconf reads the file only at start-up and rewrites it from memory on every discovery change, IP change, adopt or un-adopt, so any other writer is silently reverted. `config_save` refuses `network_map` (`config_load` still serves it, read only). An operator's node alias, the only node field the operator owns, goes to nodeconf with `node_set` over `/tmp/nodeconf.ipc`, directly, not through the engine; `role_id`/`hostname` are nodeconf's and refused. nodeconf handles `node_set` from cuems-nodeconf `3d3601d` (`0.1.1-1`, on cuems-utils `38d2ede`; UR-8 and gate G4 closed). An older daemon answers "unknown action: node_set", which the editor relays as `nodeconf_error`. Treat that as unavailable, not as a bug.
- **A `settings` `config_save` needs the engines restarted; the editor only says so** (002 FR-016, FR-021). The reply's `restart` names `cuems-controller-engine`, and `cuems-node-engine` where it runs (the editor cannot tell). Both cache the configuration at start-up and nothing reloads it.
- **`config_save` backs the replaced file up into `<library>/trash/config/<scope>_<stem>_<YYYYmmddTHHMMSS>.xml`** (002 FR-015a; scope `controller` or the project's `unix_name`), under a per-file lock after the `base_revision` check. If the backup cannot be written, nothing is saved. One copy per save accumulates, and no UI purges them yet (002 plan Complexity Tracking).
- **The repair gate is per project and outlives the connection** (002 US1). `server.repair_gates[project_uuid]` holds the outstanding load report; each session acknowledges for itself. It survives a reconnect (same `session_id`) and, because a save with no state re-derives it from the script on disk, an editor restart, a second session and a stale tab. A changed script (md5) or a changed media row (rows digest) gets a new `report_id` and drops every acknowledgment. A clean project's save adds no hash and no load.
- **The media columns are migrated at start-up, and a save writes each cue's media values from its row** (002 US6, from 869fat84r `0b291d1`). `ensure_media_columns` adds `pixel_width`/`pixel_height`/`file_size`/`file_md5` to `media` at every start (additive; a failure stops the start). The save fills each media cue's values from its library row through the `Media` attribute setters (never item assignment: `Media` is a dict and item assignment bypasses the setters); an `AudioCue` never carries a pixel size. A value present in the file that differs from the row is reported at load in `document_load_report.media_repairs` and needs the same acknowledgment as a script repair; a merely missing value is added silently. A later media check (re-probing, the deferred half of 869fat84r) must add its findings to `media_repairs` and must never send a frame of its own that gates a save (002 FR-046).
- **The media check is a projection, not a second reader** (003 US3, from 869fat84r D20). `media_check_report` (`CuemsMediaRefresh`: `open` read-only, `ready` before the engine load, `save` after a save) groups the same `media_repairs` that `document_load_report` carries (`CuemsDBProject.media_staleness`, on the object loaded by `CuemsScript.load_with_report`). It never gates a save and never touches `server.repair_gates`; its in-flight registries and marks are request de-duplication, outside `GateState`. The frame is the one released in `0.1.0rc1-4`, byte for byte, key order included: `tests/data/golden/` holds the released producer's frames (README names the source commit and method). Do not read the script a second time (`xml.etree`, `XmlReaderWriter`): `tests/test_retired_surface.py` fails on it.
- **`project_status` is three-state: `running` / `loaded` / `none`** (cuems-engine rc6-4). `CuemsWsUser._engine_running` returns `True` only for `running`, `False` for `loaded` and `none`, `None` for no answer. The released code mapped `loaded` to `None` ("silent") and skipped the check whenever a project was loaded but stopped.
- **The save gate reads the current wire.** Since cuems-utils 013 a media cue travels as `{"Cue": {"class": "audio"|"video", ...}}`; the 869fej07m gate (`validate_media_cues_in_contents`) also still accepts the pre-013 `AudioCue`/`VideoCue` wrappers. A gate that only knew the wrappers refuses nothing on the current wire (found in 003: 12 of its 18 tests failed once the fixtures were current).
- **The editor does not write the script itself.** `CuemsScript.save` is atomic and keeps the file's mode; it raises when it cannot create its temporary file in the project directory (the released `0.1.0rc1-4` editor wrote in place; reported to cuems-utils). Do not re-introduce a writer (`tests/test_retired_surface.py`).
- **`stop_project` needs cuems-utils at or after the re-cut** of its `xml-refactor-merge-candidate`: the candidate tag `4b336cd` has no `stop_project` in `script.xsd` and raises a bare `KeyError('file_name')` for a media block without a file; `387598e` has both fixes. Five tests are strict xfails that turn red (XPASS) on the re-cut; remove their markers then (`evidence/stop-project-compat.md`).
- **Released builds are checked by a test.** `tests/data/released-builds.txt` lists every shipped Debian build; `tests/test_changelog_complete.py` fails if `debian/changelog` or `CHANGELOG.md` loses one, if the top entry stops matching the version sites, and (with the release tags fetched) if an entry differs from its tag. Add a line when you release; the rig build `0.1.0rc1-5+nodeadopt2` is deliberately excluded.
- During the nodeconf transition, operators hand-populate `<role_id>`/`<alias>`/`<hostname>` in `network_map.xml`; restart the editor so the merged dict picks up the new fields. `cuems-frontend` falls back to a legacy `Node ${index + 1}` label when both `alias` and `role_id` are absent — partial migrations are safe.
