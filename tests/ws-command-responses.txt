Payload version (editor <-> UI wire version; NOT doc_version)

{"type": "payload_version", "value": <int>} is the first frame on every
connection, before users, session_id and initial_mappings. A peer that never
sends it speaks version 0, the wire before 001. Bump +1 when an existing
message loses, renames or reorders a key, changes a value's form (the string
booleans included) or changes audience. Do not bump for a new message type
or a new optional key. Every bump is a row here; tests/test_payload_version.py
fails if the advertised integer has none.

payload_version 1: the 001 coordinated-tag wire. project deltas (a) (b) (c);
initial_template no longer sent (clients build from schema_descriptor's
per-type instance); the node arrays and nodeconf_available move from
initial_mappings to node_list, which initial_mappings no longer carries.

schema_descriptor / config_save (caller only)

schema_descriptor answers with ConfigManager.get_schema_descriptor for the
named schema, rendered as JSON: enums as their values, a default that is a
factory or absent as null (as "instance" renders it). An unknown name is the
error frame. config_save refuses "script" (use project_save),
"hardware_outputs" (no model bindings), anything that is not a schema name,
and default_mappings.xml. "settings" and "network_map" persist through
ConfigManager.from_json (cuemsutils 014 closed 001 upstream report UR-5); a
successful "network_map" save also runs the all-session node refresh, same as
nodelist_modify. "project_mappings" / "project_settings" still answer the
error frame: save_project_mappings / save_project_settings need a
project_uname this action's wire shape does not carry.

initial_template (retired at payload version 1)

No longer sent. Clients build a new script from schema_descriptor("script")'s
per-type "instance". Until 001 milestone 2 it was sent on connect, before
initial_mappings. The value is
{"CuemsScript": <ConfigManager.generate_example(SchemaName.SCRIPT)>}. Until
001 it was cuemsutils' create_script(), deleted upstream. Against that
baseline (v0.1.0rc14, specs/001-cuems-utils-migration/evidence/
create-script-baseline.json) the value differs by exactly these deltas,
pinned by tests/test_initial_template.py:

  (a) every boolean is the string "True" / "False", not JSON true / false
      (the same form the "project" frame already uses)
  (b) ui_properties scalars are strings: 0 -> "0", null -> "None"
  (c) a hardware cue's key is "Cue" with "class" ("audio", "video", "dmx")
      as its last key, not "AudioCue" / "VideoCue" / "DmxCue"; a hardware
      cue output's key is "CueOutput" with "class" last, not
      "AudioCueOutput" / "VideoCueOutput" / "DmxCueOutput". ActionCue,
      FadeCue and CueList keep their keys
  (e) hardware cues have no "fade_profiles" key
  (f) Media.duration is {"CTimecode": "HH:MM:SS.mmm"}, not a bare string
  (d) example values, not empty ones: ids, created / modified, name,
      description, file_name, master_vol, output_name, output_vol,
      channel_vol, action_target and CTimecode values. Keys and their order
      are unchanged; only these values differ

Consumer: cuems-frontend src/app/services/projects/projects.service.ts:240
(type check), :243 (writes localStorage "initial_template"), :159 (reads it
back on start). A cached pre-001 template stays in localStorage until the
next connect overwrites it, and since it is no longer sent, nothing
overwrites it any more: the frontend must stop reading it.

project (reply to project_load)

The value is CuemsScript.to_wire() of the script on disk, built once by the
library's load and not walked afterwards. Opening a project does not write
its file. Payload version 1 (not a bump to 2) differs from the pre-001 frame
(specs/001-cuems-utils-migration/evidence/project-capture/) by exactly
these, (d) sanctioned 2026-10-02:

  (a) "schemaLocation" is absent (it was a top-level key beside CuemsScript)
  (b) Media.duration is {"CTimecode": "HH:MM:SS.mmm"}, not a bare string
  (c) a hardware cue's key is "Cue" with "class" ("audio", "video", "dmx",
      or any other string the document carries) as its last key; a hardware
      cue output's key is "CueOutput" with "class". ActionCue, FadeCue and
      CueList keep their keys. "AudioCue" is not written back

Key order otherwise, and "True" / "False" strings, are unchanged. doc_version
is never a key. Pinned by tests/test_project_payload.py. A pre-05 UI
mis-reads (c), which is why the milestone 1 checkpoint is not deployed.

  (d) a video cue whose document has no <opacity> carries "opacity": 100
      (the VideoCue default; opacity is a script.xsd field), before "class"

Consumer: cuems-frontend src/app/services/projects/projects.service.ts:120
declares schemaLocation: string as required.

Load reports and the save gate (001, milestone 2; audience: the session only)

Every successful project_load is followed by document_load_report, also for
a clean load (outcome "clean", empty lists). It is never omitted and never
null. outcome "converted" / "repaired" means the library changed the
document in memory: the file on disk is NOT written by opening it
(file_differs_from_loaded true). repairs[] items are {field_path
"<cue_id>/<field>", previous_value, substituted_value, rule_name}; values
are JSON-safe (a CTimecode as its string, None as null). conversions[] items
are {from_version, to_version, description, dropped_elements[]}.
file_differs_from_loaded is a JSON boolean: editor state about the file, not
a cms:BoolType field.

document_load_failed replaces both frames when the library refuses the
document: an unrepairable value (e.g. an action_target naming no cue) or a
document newer than the library (cue_id and field null). message is the
library's text. next_steps is always all three. The session stays up and
the project stays in project_list. A malformed file still answers with the
generic error frame.

project_save of a project this session opened as converted / repaired is
refused (reason "unacknowledged") until this session sends
repair_acknowledge with that report_id. Another session's acknowledgment
does not count, and a new load replaces the report. The first save after
acknowledgment moves the file on disk into <library>/trash/projects/ as
<unix_name>_<YYYYmmddTHHMMSS>_<script_file_name> before writing the repaired
document; if that move fails, nothing is saved (reason "preserve_failed").

project_duplicate gains an optional "report" (same shape as
document_load_report's value) when the source was not clean. The copy is the
repaired document; the source is not overwritten and no acknowledgment is
needed. New optional key, so not a payload-version bump.

New message types do not bump the payload version.

Nodes: adoption

The node list is pushed as "node_list" on connect (after initial_mappings),
after a successful nodelist_modify, and whenever cuems-nodeconf rewrites
network_map.xml (the editor watches its mtime). "nodelist_get" is only for
refreshing on demand without reconnecting; it replies with the same payload,
so a client needs no extra handling for it. Audience: all sessions for the
push, the caller for nodelist_get.

    value.nodes              adopted nodes
    value.new_nodes          discovered, not adopted yet
    value.nodeconf_available false = cuems-nodeconf is not running on this
                             host, so every adopt/un-adopt WILL fail. Grey the
                             controls instead of letting the operator click.
                             Sampled when the frame is built. It is not on any
                             node and not in initial_mappings.

Before payload version 1 all of this rode inside "initial_mappings" (version
0). initial_mappings is now the output mapping document alone: number_of_nodes,
defaults, and its nodes / new_nodes as the document has them (devices, no
status). The mixers that read it from localStorage need the 05 eviction.

Each node carries uuid, mac, name, ip, node_role, adopted, online and the
optional identity fields role_id / alias / hostname, in the library's wire
form: uuid a string, adopted / online "True" / "False" (not JSON true /
false), node_role "controller" / "node" / .... There is no node_type. A node
that has a mapping node keeps that mapping node's keys, output blocks
(devices / device / class) included, in place. `online` is nodeconf's
discovery view (refreshed within ~30 s), NOT runtime liveness.

Before 001 these frames lost nodeconf_available and node_role, and carried
JSON booleans: json.dumps of the library mappings object re-projected every
node through the mappings schema (specs/001-cuems-utils-migration/evidence/
mappings-capture/). tests/test_node_merge.py pins the difference.

network_map_error (all sessions; new in 001, not a payload-version bump)

    ->  {"type": "network_map_error", "value": {"kind": "duplicate_identity",
         "identity": "<uuid string>", "file": "<path of network_map.xml>"}}
    ->  {"type": "network_map_error", "value": null}

network_map.xml names one node identity on two rows. The editor does not
retry that read (the file will not become unique by waiting), keeps serving
the last good node list, logs once per identity, and broadcasts the first
frame to every session, and to each session that connects while it stands
(after node_list). The next successful read broadcasts the null frame, then
the usual node_list. A nodelist_get while it stands answers the caller with
the error frame, then the last good node_list. Fix: decide
from the two rows' MACs which is the real node and run cuems-init-node
--remint (the library's message, in the editor log, says the same).

For runtime liveness use "node_status": `alive` is the engine's sub-second
ping/pong, the only signal the GO gate trusts, and `age_s` says how old that
probe is. Show the two as SEPARATE indicators — merging them tells the operator
a node is dead when it was merely missed by the last discovery pass, or alive
when it vanished 20 s ago. A failed or timed-out node_status means UNKNOWN,
never dead: the engine serializes editor commands, so the request can queue
behind a slow project load and time out while every node is healthy. Repeat
calls inside 2 s are served from a cache, so polling is cheap.

"node_status" also carries the last project load's diagnosis, relayed verbatim
from the engine:

    value.missing      node UUIDs the loaded project uses that are NOT in the
                       cluster at all (un-adopted, or never adopted)
    value.unreachable  adopted and used by the project, but did not answer the
                       engine's ping

Their cues will NOT play, and GO is deliberately NOT blocked — warn, never
block. The two cases need different actions from the operator (adopt it vs go
and switch it on), so show them apart. Both are re-read on every call, outside
the 2 s cache, so they are never stale. The same lists are also pushed over the
OSC channel at load time as /engine/status/cluster_warning (a JSON string, with
a per-load `load_id`), and replayed to WebSocket clients that connect after the
load. Empty lists mean a clean load and are sent on purpose: they are what
erases a previous warning.

nodelist_modify is refused, with the reason in the error frame, when:
  - a project is running or merely loaded (unload it first),
  - the node is offline, or is the controller (it cannot be un-adopted),
  - cuems-nodeconf is not responding.

The "nodeconf" action is a legacy stub: nodeconf implements no such verb, so it
only ever times out. Do not wire it into the UI.
